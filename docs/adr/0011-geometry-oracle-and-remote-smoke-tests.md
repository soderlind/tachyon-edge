# Verify with a geometry oracle and remote smoke tests

Golden image bytes are no longer the gate. Verification has three layers:

1. **Geometry oracle:** for a matrix of argument combinations, Tachyon v3.0.8's Sharp pipeline (`tests/oracle`, dev-only) and the Worker's geometry planner must produce the same output dimensions for the same Original. This includes rotated EXIF images, zoom, `px` quirks, and enlargement edge cases.
2. **Plugin Contract tests:** the Worker runs against a Sharp-backed fake Images binding that implements the operations the planner emits. The tests cover the URL forms generated by the plugin, both presign forms, `X-WebP`, status codes, headers, caching, and private prefixes.
3. **Remote smoke test (before production traffic):** a deployed Worker with the real Images binding must reproduce the oracle dimensions for the fixture set, honor EXIF orientation, and apply chained `trim`, `cover`, and `border` in order.

### Remote smoke checklist

`tests/remote/smoke-remote.ts` runs these checks against a deployed Worker (`npm run test:remote`; fixtures are uploaded by `tests/remote/prepare.mjs`). The fake binding encodes assumptions about the real binding, and the smoke test confirms them. Results from the first deployment (wrangler 4.157.0, 2026-11-04), 90 of 90 checks passing:

- [x] For 6 Originals × 13 argument sets plus animated GIF and WebP, the dimensions and `Content-Type` match the Tachyon v3.0.8 oracle.
- [x] `trim` on an EXIF-rotated JPEG (orientation 6) crops in display coordinates, so no conversion to stored coordinates is needed.
- [x] A one-pixel `trim` edge is treated as pixels, not as a fraction.
- [x] `border` adds exactly the requested pixels in the `background` colour.
- [x] `cover` with `{x, y}` gravity selects the same region as Tachyon's compass gravity.
- [x] Animated GIF and WebP stay animated and keep their frame size.
- [x] AVIF Originals are sized with `IMAGES.info()` and served as `image/avif`.
- [x] Missing, private-unsigned, invalid-crop and `X-WebP` cases return the contract statuses and headers.
- [ ] ~~PNG with an explicit quality is palette-encoded.~~ It is not: the binding ignores PNG quality and writes truecolor. This is now a deviation (ADR 0006).

A second run (2026-11-04, 132 of 132 checks passing) added EXIF-oriented PNG and WebP Originals and AVIF assertions:

- [x] The binding does not apply orientation stored in PNG `eXIf` or WebP `EXIF` chunks. The Worker's explicit `rotate` (clockwise) and `flip` operations reproduce Tachyon's display for all eight orientations, and `trim` then works in display coordinates.
- [x] AVIF Originals resized to `w=300` return 200, `image/avif` and width 300. Set `TACHYON_SMOKE_SKIP_AVIF=1` on accounts without AVIF support.

The first deployment also found that the binding rejects `anim: true` for JPEG and PNG output with error 9401 ("Animated output is only supported for GIF or WebP"). The fake binding now enforces the same rule.

Unexpected errors are logged without query strings or secrets and return a sanitized 500. Origin failures return 502.
